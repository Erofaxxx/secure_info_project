### Q: Как установить зависимости?

```bash
pip install -r requirements.txt
```

```bash

python3 -m pip install -r requirements.txt
```

```bash

```

Введите адрес сервера (localhost для локального тестирования).

## 🔐 Безопасность и шифрование

### Q: Что такое E2E шифрование?

**End-to-End (E2E) шифрование** означает, что:
- Сообщения шифруются на устройстве отправителя
- Расшифровываются только на устройстве получателя
- Сервер не может прочитать сообщения
- Даже администратор сервера не имеет доступа к переписке

### Q: Какое шифрование используется?

**Гибридная схема:**
- **RSA 2048 бит** - для обмена ключами (асимметричное)
- **AES-128 (Fernet)** - для шифрования сообщений (симметричное)
- **bcrypt** - для хеширования паролей
- **OAEP padding** - для защиты RSA

### Q: Почему не просто RSA для всего?

RSA медленный для больших данных. Мы используем **гибридную схему**:

1. Генерируем случайный AES ключ (быстрый)
2. Шифруем сообщение AES ключом (быстро!)
3. Шифруем сам AES ключ RSA (медленно, но ключ маленький)

Итог: Безопасность RSA + скорость AES

### Q: Где хранятся приватные ключи?

**Только на клиенте!** Приватные ключи:
- Генерируются при запуске клиента
- Хранятся в памяти приложения
- НИКОГДА не отправляются на сервер
- Удаляются при закрытии приложения

**Для постоянного хранения** (не реализовано в учебной версии):
- Можно сохранять в файл, зашифрованный паролем пользователя
- Использовать OS keychain (macOS) или keyring (Windows/Linux)

### Q: Может ли сервер прочитать мои сообщения?

**НЕТ!** Сервер хранит:
- Зашифрованные сообщения (нечитаемые)
- Зашифрованные AES ключи (нечитаемые без приватного ключа)
- Публичные ключи (они и должны быть публичными)

Проверьте сами:
```bash
sqlite3 messenger.db
SELECT * FROM messages;
```

Все сообщения выглядят как случайный набор символов в base64.

### Q: Что если взломают сервер?

Даже если злоумышленник получит:
- ✅ Доступ к серверу
- ✅ Копию базы данных
- ✅ Все публичные ключи

Он **НЕ СМОЖЕТ** прочитать сообщения, потому что:
- ❌ У него нет приватных ключей пользователей
- ❌ Приватные ключи только на клиентах

### Q: Безопасны ли пароли?

Да! Пароли хешируются **bcrypt** с:
- Автоматической солью (случайной строкой)
- Cost factor 12 (много итераций)
- Защитой от rainbow tables
- Защитой от брутфорса (медленное хеширование)

В базе хранится только хеш, не сам пароль.

## 🐛 Решение проблем

### Q: "Connection refused" при подключении клиента

**Возможные причины:**

1. **Сервер не запущен**
   ```bash
   python server.py
   ```

2. **Неправильный IP адрес**
   - Для локального: `localhost` или `127.0.0.1`
   - Для удалённого: проверьте IP сервера

3. **Firewall блокирует порт 5555**
   ```bash
   # На Ubuntu
   sudo ufw allow 5555/tcp
   ```

4. **Сервер слушает только localhost**
   - Убедитесь что в server.py:
   ```python
   server = MessengerServer(host='0.0.0.0', port=5555)
   ```

### Q: Ошибка "Address already in use"

Порт 5555 уже занят другим процессом.

**Решение:**
```bash
# Найти процесс на порту 5555
lsof -i :5555

# Или
netstat -tulpn | grep 5555

# Убить процесс (замените PID)
kill -9 PID
```

Или измените порт в server.py и client.py.

### Q: Клиент не видит список пользователей

**Проверьте:**

1. Есть ли зарегистрированные пользователи?
   ```bash
   sqlite3 messenger.db "SELECT * FROM users;"
   ```

2. Правильно ли вы вошли в систему?
   - Сначала зарегистрируйтесь
   - Потом войдите

3. Есть ли другие пользователи кроме вас?
   - Запустите второго клиента
   - Зарегистрируйте второго пользователя

### Q: Сообщения не отображаются / не расшифровываются

**Для отправленных сообщений:**
- Отправленные сообщения зашифрованы для получателя
- Отправитель не может их расшифровать (это нормально!)
- Только получатель может прочитать

**Для полученных сообщений:**
- Должны расшифровываться автоматически
- Если нет - возможно ключи не синхронизированы

**Решение:**
- Перезапустите клиенты
- Убедитесь что оба пользователя зарегистрированы с публичными ключами

### Q: GUI не запускается / черный экран

**На Linux может требоваться:**
```bash
sudo apt-get install python3-tk
```

**На macOS:**
- Используйте официальный Python с python.org
- Или установите через brew: `brew install python-tk`

**На Windows:**
- Переустановите Python, убедитесь что выбрана опция "tcl/tk"

### Q: Ошибка "Permission denied" при запуске сервера

**Linux/macOS:**
```bash
# Сделайте файл исполняемым
chmod +x server.py

# Или запускайте через python
python server.py
```

Если порт < 1024 (например 80), нужны root права:
```bash
sudo python server.py
```

**Но лучше используйте порт ≥ 1024** (например, 5555)

## 💻 Использование

### Q: Как зарегистрироваться?

1. Запустите клиент: `python client.py`
2. Введите адрес сервера
3. Нажмите **"Регистрация"**
4. Введите username и password (минимум 4 символа)
5. Нажмите **"Регистрация"**
6. Теперь войдите с этими данными

### Q: Как отправить сообщение?

1. Войдите в систему
2. В левой панели увидите список пользователей
3. Кликните на пользователя
4. Введите сообщение в поле внизу
5. Нажмите Enter или "Отправить"

### Q: Как увидеть историю сообщений?

История загружается автоматически при открытии чата:
- Кликните на пользователя в списке
- Появятся все предыдущие сообщения

### Q: Сколько чатов можно иметь?

По умолчанию **максимум 5 чатов**.

Чтобы изменить, в **client.py** найдите:
```python
return response['users'][:5]  # Измените число
```

### Q: Как узнать что сообщение доставлено?

В текущей версии нет статусов доставки (checkmarks).

**Для добавления:**
- Нужно реализовать систему подтверждений
- ACK сообщения от сервера
- Обновление GUI

Это возможное улучшение для будущих версий.

## 🌐 Сервер

### Q: На каком порту работает сервер?

**Порт 5555** (можно изменить в server.py)

### Q: Как изменить порт?

**server.py:**
```python
server = MessengerServer(host='0.0.0.0', port=8080)  # Измените 5555 на 8080
```

**client.py:**
```python
def __init__(self, server_host: str = 'localhost', server_port: int = 8080):  # Измените
```

Не забудьте открыть порт в firewall!

### Q: Как посмотреть логи сервера?

**Если запущен напрямую:**
- Логи выводятся в терминал

**Если запущен через systemd:**
```bash
sudo journalctl -u securechat -f
```

**Если настроили файлы логов:**
```bash
tail -f ~/securechat/server.log
```

### Q: Сколько клиентов может подключиться?

Теоретически **неограниченно** (ограничено только ресурсами сервера).

Для каждого клиента создаётся отдельный поток (threading).

### Q: Как остановить сервер?

**В терминале:**
```bash
Ctrl+C
```

**Если через systemd:**
```bash
sudo systemctl stop securechat
```

### Q: Как посмотреть зарегистрированных пользователей?

```bash
sqlite3 messenger.db
SELECT username, created_at FROM users;
.quit
```

Или:
```bash
sqlite3 messenger.db "SELECT COUNT(*) FROM users;"
```

## 🎓 Для учебного проекта

### Q: Как продемонстрировать E2E шифрование?

1. **Запустите демо:**
   ```bash
   python test_encryption.py
   ```

2. **Покажите базу данных:**
   ```bash
   sqlite3 messenger.db
   SELECT sender, receiver, substr(encrypted_message, 1, 50) FROM messages;
   ```
   Сообщения нечитаемы!

3. **Объясните код:**
   - Откройте `encryption.py`
   - Покажите функции `encrypt_message()` и `decrypt_message()`
   - Объясните гибридную схему

### Q: Что можно улучшить?

**Для продвинутого проекта:**

1. **Perfect Forward Secrecy** - регулярное обновление ключей
2. **Аутентификация ключей** - защита от MITM
3. **TLS/SSL** - шифрование соединения к серверу
4. **Групповые чаты** - шифрование для нескольких участников
5. **Отправка файлов** - с шифрованием
6. **Статусы доставки** - прочитано/доставлено
7. **Онлайн статус** - показывать кто онлайн
8. **Эмодзи и форматирование** - богатый текст
9. **Уведомления** - системные уведомления
10. **Мобильная версия** - Kivy для Android/iOS

### Q: Какие уязвимости есть в учебной версии?

**Намеренные упрощения:**

1. **Нет TLS** - метаданные не защищены (кто с кем общается)
2. **Нет аутентификации ключей** - возможен MITM на этапе обмена ключами
3. **Нет Forward Secrecy** - компрометация долгосрочного ключа раскрывает все сообщения
4. **Приватные ключи в памяти** - не сохраняются между сессиями
5. **Нет проверки подлинности сервера** - клиент не проверяет что подключился к настоящему серверу

**Но:** Базовое E2E шифрование работает правильно!

### Q: Какие технологии использованы?

- **Python 3.8+** - язык программирования
- **CustomTkinter** - современный GUI
- **cryptography** - RSA, AES, Fernet
- **bcrypt** - хеширование паролей
- **SQLite** - база данных
- **socket** - TCP сокеты
- **threading** - многопоточность

## 📊 Производительность

### Q: Насколько быстро работает шифрование?

**Примерные значения:**
- Генерация RSA ключей: ~100-200ms (один раз при старте)
- Шифрование сообщения: ~5-10ms
- Расшифровка: ~5-10ms
- Отправка по сети: зависит от интернета

Для обычной переписки - мгновенно!

### Q: Можно ли отправлять длинные сообщения?

Да! Гибридная схема позволяет шифровать сообщения любой длины:
- AES шифрует само сообщение (без ограничений)
- RSA шифрует только маленький AES ключ (32 байта)

Практический лимит: ограничен только размером TCP пакета и памятью.

## 🔧 Разработка

### Q: Как изменить дизайн?

CustomTkinter использует цветовые темы:

```python
# В client.py
ctk.set_appearance_mode("dark")  # или "light"
ctk.set_default_color_theme("blue")  # или "green", "dark-blue"
```

Или создайте свою тему в JSON файле.

### Q: Как добавить новые функции в протокол?

1. **В server.py** добавьте новый command:
   ```python
   elif command == 'YOUR_COMMAND':
       # обработка
       response = {'success': True}
   ```

2. **В client.py** создайте функцию:
   ```python
   def your_function(self):
       data = {'command': 'YOUR_COMMAND'}
       return self.send_request(data)
   ```

### Q: Где хранится база данных?

В той же директории где запущен **server.py**:
```
./messenger.db
```

Для изменения местоположения, в server.py измените:
```python
conn = sqlite3.connect('/path/to/your/database.db')
```
